# Codex Desk

一个以 Flutter 构建的本地优先 Codex 桌面客户端。首个目标平台是 macOS。

后续开发任务、优先级与发布前置条件见 [ROADMAP.md](ROADMAP.md)；每项工作完成后会同步更新该清单和本文档。本地工作树的产品边界、任务执行目录、Git 生命周期、增量 Handoff、历史恢复、事务回滚、安全清理和测试方案见 [LOCAL_WORKTREE_DEVELOPMENT.md](LOCAL_WORKTREE_DEVELOPMENT.md)。

已完成任务提醒的已查看状态会随对应工作区的加密历史缓存持久化；应用重启或侧栏重建后不会重复提醒，同一任务再次成功完成时会重新进入未查看状态。未查看的成功结果以任务行尾部的小蓝点提醒，包括完成时仍在当前会话中的任务；停止或取消的任务不会显示蓝点。当前会话已经位于时间线底部，或用户随后滚动到底部时，会自动确认并隐藏“任务已就绪”和小蓝点；仍停留在上方阅读时会保留提醒，也可点击对应任务行清除。鼠标移入任务行时蓝点暂时隐藏并让位给快捷操作。点击 Dock 图标切回应用时，若右侧仍显示发出完成通知的会话，会自动清除该会话的 Dock 红点；设置、插件等其他工作区不会清除提醒，其他未查看任务继续保留。切换或新建项目时不会带入上一项目的已查看状态。

平台支持范围与 Windows/Linux 评估见 [PLATFORM_SUPPORT.md](PLATFORM_SUPPORT.md)。

## 当前进度

- 新线程启动会并行发起任务列表刷新与 `turn/start`：任务列表请求无论缓慢或暂时不可用都不会让 Composer 停在发送前；在服务端接受回合前仍隔离完成事件，回合请求发出后正常接收流式回复。显式切换到其他工作区时会等待首次恢复完成，避免旧项目的自动恢复请求与用户明确选择的任务竞争。
- 实时回复兼容仅在 `item/completed` 携带完整 `agentMessage` 文本的运行时：客户端会回填最终答案，不会只显示“任务完成”而缺少助手反馈；若同时收到流式增量，则以完成事件中的完整文本校正截断内容。
- `/目标` 会把目标文字同时作为首轮任务指令和完成条件，在同一线程的 turn 启动握手中先完成持久目标写入并立即发起任务；不会因刷新侧栏或切换到其他任务而中断。重新打开任务会通过 `thread/goal/get` 恢复目标；Composer 上方的进度行显示服务端状态、token 预算和已用时间，并可暂停、恢复、编辑或清除目标。相关更新与清除通知按线程隔离，后台目标不会污染当前会话。
- 目标状态为“需要输入”（`blocked`）时，目标卡不会失去操作能力：可直接点击恢复，或发送下一条消息时自动先恢复目标再提交回合；只有完成、用量/预算耗尽或主动清除才不提供暂停/恢复操作。
- Goal 生命周期状态变化会在当前会话时间线追加一次明确的“目标状态”记录（启动/恢复、需要输入、暂停、完成或限制），不会把重复事件渲染成大量条目；后台线程事件仍按线程隔离。
- Goal 回合在尚无具体实时活动时，Composer 上方的低干扰 loading 会显示“正在推进目标：…”并压缩过长目标文字，避免只显示无上下文的“正在思考”。
- 左侧项目树按视口惰性构建；已缓存任务之间来回切换会直接复用保活时间线，不再重复刷新完整任务列表。后台任务运行期间切换项目时，配置、任务、归档与技能等彼此独立的数据并行刷新，减少等待和侧栏卡顿；首次打开未缓存任务仍会读取权威历史并刷新任务状态。
- 本地历史导入/导出已接入项目菜单：运行中拒绝导入，并且只在新快照成功落盘后替换当前项目缓存；写入失败会恢复导入前的任务、时间线、置顶和已查看状态。
- 截图附件的生命周期与任务语义对齐：归档只隐藏任务，不再删除其持久图片；只有永久删除任务才回收无引用附件。非当前项目的后台任务完成时也会保留该项目全部用户图片映射。
- 全局快捷键已接线：`Command+,` 打开设置，`Command+N` 新建对话，`Command+K` 搜索任务，运行中按 `Esc` 停止当前任务；macOS 的 `Preferences…` 菜单与 `Command+,` 使用同一设置入口。文件变更预览和左右窗格调宽同时提供键盘与读屏语义。
- 设置搜索会按关键词跳转到对应分类。尚未接入持久化或真实行为的设置项统一标记“（待开发）”并禁用，不再以页面局部假状态显示为已生效。
- 插件、MCP、Git 和 Codex CLI 探测改用可回收子进程：超时后会先终止、必要时强制退出并等待回收，避免界面已报失败时旧命令仍在后台继续改动状态。
- Composer 的目标会以内联模式显示：`/目标` 与“添加 → 目标”都会在输入框内展示目标提示和底部“目标”标识，不弹出对话框；退出该模式会恢复切换前草稿，提交则按 Codex Goal mode 语义以目标文字同时启动首轮任务并定义完成条件。目标成功提交后会持久化到当前任务，随后从输入框移除；不会作为下一条消息的重复草稿标签显示。
- 计划模式通过 App Server 原生 `collaborationMode.mode = plan` 切换，并支持 `Shift+Tab`；运行中的 turn 会同时禁用菜单、快捷键和标签关闭入口，不会把普通方向提示伪装成计划模式。如果运行时尚未返回协作模式必需的模型，提交会保留输入并显示错误，不会静默降级为普通模式。服务端完成的权威 `plan` item 会立即写入当前时间线并去重，重新打开历史时保持同一计划内容。
- Composer 选择的普通文件和目录会在保留可读路径提示的同时，以 App Server `type: mention` 结构化输入发送；图片继续使用 `localImage`，Skill 继续使用 `skill`，避免把所有附件都降级为纯文本路径。
- Skill 列表刷新后会重新校验 Composer 中的已选路径；被禁用、删除或不再由 App Server 公布的 Skill 会立即从选中状态移除，不会以过期上下文提交。
- “当前项目上下文”入口只发送当前工作区路径；由于没有 IDE 宿主桥接，不再把它描述为包含选区、光标或打开文件的完整 IDE 上下文。未选择项目时，`@` 与添加菜单中的该入口都会禁用并说明原因，不会清空输入后静默无操作。
- `/` 菜单中的 IDE 上下文在未连接 IDE 宿主时保持禁用；当前项目路径上下文仍从 `@`/添加菜单使用，避免把项目路径伪装成 IDE 选区数据。
- Composer 的 `@`/`/` 菜单打开或查询变化时会默认选中首个可执行项，禁用行不会截获 Enter；鼠标悬停可用行会同步键盘选中态，随后按 Enter 与点击执行同一动作。
- 侧边聊天命令在宿主未注入打开回调时会显示明确不可用反馈，不会静默吞掉用户操作。
- “录制技能”在当前运行时没有公开录制协议，因此在 `@`/添加菜单中保持禁用，不再用 `skill-creator` 和提示词模拟已完成的录制流程。
- 跨工程切换会先捕获并后台保存当前工程历史，不再让加密/磁盘写入阻塞新工程的可见切换；运行时完成握手后立即可用，配置、账户、模型、任务列表、归档和技能改为并行后台刷新。旧工程仍有任务运行时也不会等待这些远端列表，显式点击的目标任务优先于该工程上次任务的自动恢复；所有迟到结果按工程与运行时代次隔离。
- 文件变更事件兼容直接项、`item` 包装项及 `file_change` 类型别名；只要 App Server 已报告有效路径，会话摘要、任务文件和审查入口都会保留该记录，不会因协议字段变体而显示“暂无”。
- 重启后自动重新挂接上次打开的任务时，如果服务端历史未携带文件变更项，会保留本地加密快照中的任务文件与 Diff 摘要，避免恢复流程将右侧数量误清空；新回合仍按现有单轮语义清理摘要。
- 文件变更和整轮 Diff 到达时会立即安排本地历史保存，不再依赖后续 `turn/completed` 才落盘；运行中的任务若应用重启，也能保留最近一次已收到的任务文件摘要。
- 本地历史快照按 thread 保存各任务最近的文件摘要与 Diff；切换任务后再返回，或重启后打开非上次活动任务，也不会因全局快照只有一个文件集合而丢失摘要。
- 按 thread 的文件快照会随本地历史导入和失败回滚一起恢复；永久删除任务时同步清理对应摘要，避免导入覆盖或删除后遗留数据。
- macOS 剪贴板临时文件仅允许从应用受管的临时目录删除直接文件；嵌套路径、目录外路径及受管目录内的子目录均会被拒绝，对应原生 Xcode 测试已覆盖。

- macOS 主窗口使用内容延伸式透明标题栏：独立的灰色标题条、窗口标题文字和底部分隔线已移除，工作区内容延伸到窗口顶边；红黄绿窗口按钮仍保留，“Xedoc / 已就绪”位于按钮下方，并按左侧按钮区与侧栏右缘留出紧凑边距。
- 左侧菜单使用独立的 Codex 深色表面（深色模式为 `#282A2B`，浅色模式为柔和灰白），与中间工作区形成清晰层次；拖动侧栏分隔条调整后的宽度会写入本地 UI 偏好，应用重启后自动恢复（限制在 210–420px）。
- 会话窗口右侧现在内嵌环境信息面板，按参考图与对话内容并列显示；任务文件明细列表不再单独展示，变更入口仍保留。
- 会话顶部栏整块内容固定贴齐工作区左侧，不再因顶部栏宽度小于工作区而被居中并在左边留下大块空白。
- 会话时间线的滚动内容与底部 Composer 共用左右 24px 的对称边距，消息列表、分隔线、文件变更卡片和输入框保持同宽且居中。用户消息导航仍作为独立浮层固定在左侧。
- 会话滚动列表、Composer 和非阻塞错误提示共用居中的 790px 内容列，保持同宽、同中心线和对称内边距；错误提示在宽窗口下不会横跨整个会话视口。
- 新建任务欢迎页提供四个 Codex 风格任务入口；点击“探索并理解代码”会隐藏初始入口，并沿 Composer 左边缘、紧贴其正上方通过短促的上浮淡入动画弹出“探索并了解功能的工作原理”“探索某项功能的实现方案”“探索并比较架构方案”“探索并编写 API 文档”四条菜单式线索，同时将“探索”填入 Composer；选择线索后替换为具体提示词并反向收起、恢复初始入口。用户自行修改输入内容时也会收起菜单，单纯移动光标或选择文字不会误触发；系统减少动态效果时禁用过渡。
- 环境信息卡按当前项目下的多根工程分组展示任务变更，包括位于主工程内部的嵌套附加工程；每个工程显示项目名和 `+新增 -删除` 行数，不再将文件数量伪装为变更统计。App Server 仅提供整轮统一 Diff 时，客户端会从 Git 文件头恢复文件清单；随后到达的仅元数据文件事件不会让下一次 Diff 更新保留旧补丁，因此环境卡、任务文件数和“最新一轮”审查始终指向同一批文件与最新内容；没有 Diff 或文件记录的空任务不会误显示 `+? -?`。点击分组中的“变更”或“任务文件”会用同一份当前任务数据打开“最新一轮”审查；“本地”、分支和 Git 操作入口则打开整个 Git 工作区，避免提示有任务变更但审查内容为空。
- 点击环境信息卡的当前分支会在该行左侧打开分支弹层，可搜索本地分支、查看当前分支与未提交文件数、切换分支，或创建并检出新分支；弹层绑定打开时的项目，项目切换后旧结果会被丢弃，冲突改动由 Git 安全拒绝。
- 展开右侧审查、浏览器或子智能体工作区时会隐藏环境信息面板，收起后恢复显示，避免与扩展工作区争夺空间。
- 右上角展开按钮默认可用；点击后显示审查、终端、浏览器和文件入口，选择后进入对应工作区或操作。
- 右侧工作区使用单击展开或收起；顶部切换按钮提供 40×40 像素命中区域，降低紧凑图标误点和漏点。
- 右侧工作区展开或收起的极窄过渡帧会暂时隐藏标签，仅保留可收起按钮，避免标签栏横向溢出；宽度恢复后标签自动重现。
- MCP 表单输入请求与权限审批使用同一套底部浮动操作卡：中性深色表面、统一边框与阴影、随窗口高度受限的滚动内容，以及一致的取消、拒绝和主操作按钮层级；当前任务的请求优先，同一优先级按到达顺序显示，避免同时堆叠遮挡 Composer。

- 子智能体在实时状态、完成记录与只读检查器中使用由子线程 ID 稳定分配的十枚头像。App Server 的 `collabToolCall` 和 `subAgentActivity` 生命周期都会即时更新会话时间线、右侧摘要与“智能体”目录；多个运行项会全部显示，完成后原位转为历史活动。点击右侧摘要的“查看全部”会主动展开工作区并打开全部已知子智能体 Tab；左侧目录仍按“已开启”和“完成”分组，点击单项会返回会话并打开对应的只读详情，不中断主会话草稿。
- 右侧工作区采用可复用的多 Tab 工作台：审查、内置浏览器、文件浏览器、会话内打开的项目文件与每个子智能体详情在同一面板中平级显示，点击已打开项只切换 Tab。会话回复中的项目文件行会在点击时重新校验磁盘边界，再按规范路径打开可关闭的文件 Tab；同一路径复用已有 Tab 并重新读取磁盘内容，多份文件可同时保留，切换项目会关闭旧项目文件并丢弃迟到的旧项目打开请求。Markdown 提供格式化预览、源码、相对文档跳转、本地图片和外部打开，相对 Markdown 链接会创建同级文件 Tab；其他 UTF-8 文本以带行号、可复制和语法着色的等宽源码视图展示。文件浏览器从当前工作区根目录开始，以真实目录名展示并支持目录展开、文件名筛选和刷新；筛选时保留目录层级，以便继续查找嵌套文件。普通文本读取量严格限制为 1 MB，二进制、非 UTF-8 和超限文件会明确提示；Markdown 单份限制为 8 MB，符号链接解析后的目标也必须位于当前工作区。所有预览均为只读。桌面布局展开时，扩展栏始终是从窗口顶端到底部的独立右栏，拥有自己的 Tab 顶部；会话顶部只属于左侧主任务。工作区展开时环境信息面板隐藏，收起后恢复；只有真正的窄屏断点才让扩展栏覆盖会话。窗口最右上角始终显示固定面板图标，收起时保留全部 Tab 状态。
- 桌面会话内容列采用固定的 Codex 风格最大宽度 790px，并在可用空间中居中显示；多出的宽度交给环境信息与审查/子智能体栏，窗口缩窄时内容列才按空间收缩，不改变输入框和时间线状态。
- 会话左侧的用户消息导航短横线固定锚定在会话窗口最左侧，不随居中的内容列或窗口宽度变化而横向漂移；导航浮层与限宽内容列分离，宽窗口下也不会被内容列边界裁掉。悬停横线会即时展开相邻标记，并立即在右侧显示对应用户消息的 Codex 风格紧凑预览；单段长消息最多展示四行，预览限制在窗口边界内并跟随导航布局变化重新对齐。快速切换会更新内容，时间线流式刷新期间保持稳定，移出消息横线（包括进入导航栏空白区域）或切换会话后关闭，点击仍定位到原消息。
- 发送前会校验剪贴板临时图片仍然存在；若系统已清理临时文件，会自动移除失效附件并提示重新粘贴，不再提交无效路径。

- writer 冲突重试在运行时暂时不可用或正在切换时会保留原提示，待连接恢复后仍可继续重试，不会出现“提示消失但任务未恢复”的卡死状态；点击后若运行时尚未连接或另一客户端仍占用 writer，提示会显示明确原因，不再表现为无响应；新建会话会清除旧会话的冲突提示，不会把它带入新会话

- 用户消息气泡整体靠右；短消息会随内容收窄，长消息在最大宽度内从左边缘自然换行，超过 16 行时会先以省略号折叠，并可在气泡内展开全文或重新收起；鼠标悬停在气泡上时，气泡下方会以悬浮层显示该条消息的本地时间，不改变消息高度或推动后续内容
- 助手回复在会话时间线中直接显示 Markdown 正文，不再于每条回复左上方重复显示“Codex”身份标签；指向当前项目现有文件的链接会显示为带文件名和图标的紧凑文件行，文件名会优先使用会话的全部可用行宽，仅在确实超过容器时才自然换行完整显示，不使用省略号；位于 Markdown 强制换行之后时会从下一行左侧对齐显示，不会与上一行的空白行盒垂直错位；缺失、越界或项目外目标仍保持普通链接并受原有安全边界限制；工具、审批、错误和系统记录的类型标题仍保留
- 文件行的解析结果只用于展示；点击、Markdown 预览读取和外部打开前都会按当前磁盘状态重新校验项目边界，文件被替换为越界符号链接时会拒绝打开。普通 Markdown 链接继续保留粗体、斜体、删除线、行内代码和链接图片等子样式；链接中的本地图片也只允许读取当前项目内目标，越界图片回退显示替代文本，图片 `alt` 会作为链接的读屏标签。助手身份不可见但会通过语义标签提供给读屏软件。异步文件行完成布局时，仅在用户仍停留于时间线底部且未开始滚动时继续贴底，包括文件行位于带横向滚动容器的 Markdown 表格内时

- 文件变更摘要卡片的标题使用 14px 半粗体，新增/删除行统计使用 13px 字号，避免在对话流中显得过大。
- 右侧检查器采用 Codex 风格的“环境信息”圆角卡片：展示本地 Git 变更、当前分支、提交/推送、创建拉取请求和比较分支入口；标题使用 15px，操作行和分组标题使用 13px，文件行使用 13px，保持紧凑的信息密度；文件变更仍以可展开行列出本次任务完整 Diff 和 AI 修改的文件
- 模型与推理强度选项由 Codex App Server 动态提供；模型气泡不显示额外图标，跟随配置简化显示为“默认”，其他模型只显示展示名称并隐藏内部模型 ID；推理强度会随所选模型联动并保存，控件只显示强度名称，两者只用于后续新建任务，不覆盖恢复的历史任务
- 运行中连续提交的“调整方向”会按序暂存在输入框顶缘；未手动调整时，当前任务及后续轮次每次结束都会取队首作为同一线程的下一轮任务发送。自动续发失败时会恢复原队列且不留下伪造的用户消息；手动调整恰逢任务结束且 `turn/steer` 未成功时也会安全转为下一轮发送，只有逐条点击删除才会丢弃
- 活跃与归档线程列表会跟随 App Server 分页加载，不限于首 50 条
- 提供“插件”管理入口：读取本机 Codex CLI 的已安装与可安装插件、当前项目目录下生效的 MCP 服务器以及 App Server 技能，支持添加本地或远程 marketplace、刷新 Git marketplace、安装插件、确认后卸载插件，以及原子启停插件、MCP 与技能；插件页会继续使用官方 CLI/curated marketplace 的实时清单，并读取每个插件 `.codex-plugin/plugin.json` 中的展示名、简介、分类和 logo（支持 PNG/JPEG 与 SVG），按官方分类分组展示；已安装插件只在“已安装”区域出现，不会重复出现在精选或分类目录中。Logo 路径会限制在插件源目录内，缺少或无法读取 logo 时会显示 Codex 风格的旋涡标记，左侧“插件”入口也复用该标记。左侧菜单项统一为 32px 高，图标与文字在行内垂直居中。配置成功后会自动重连运行时并更新生效状态。MCP 列表会标注用户、项目或托管范围：用户服务器写回 `~/.codex/config.toml`（或当前 `CODEX_HOME`），项目服务器只在 Codex 已信任当前项目时才识别并写回项目 `.codex/config.toml`，未受信任项目的同名配置不会覆盖用户级来源，无法识别配置来源的托管服务器保持只读；MCP 名称、项目信任路径与技能路径配置兼容 TOML 双引号和单引号键/字符串，启停时保留原有单引号写法且不会追加重复配置块；切换项目会清空旧列表并丢弃仍在途的旧项目刷新结果，扩展配置写入期间禁止切换主项目。插件、MCP、技能和添加服务器失败均会在当前界面显示原因；如果配置已写入而后续列表刷新失败，界面会关闭添加窗口并单独显示刷新警告，不会误导用户重复添加。插件管理会复用运行时自动发现的 CLI 绝对路径，不依赖桌面应用的 `PATH`，路径解析和每条 CLI 命令均会在 20 秒后超时；插件会展示安装策略与认证时机，OAuth/连接器授权仍由 Codex Host 在安装或首次使用时处理
- “Codex CLI”运行时窗口会展示 CLI 自动发现来源、版本与最近 stderr/协议诊断日志；日志仅在内存中保留最近 200 条，可一键复制脱敏诊断报告，不会写入对话历史
- 侧栏“Git 项目”提供当前分支、暂存/未暂存/未跟踪改动摘要、按路径搜索和状态筛选的文件列表与 Diff；可对单个文件暂存或经确认后还原，随后可显式提交、推送或通过本机已登录的 GitHub CLI 创建拉取请求；超大 Diff 会明确提示仅显示前 120,000 个字符
- 线程列表支持批量归档；单个活跃或归档线程可在二次确认后永久删除，删除会同时移除 App Server 定义的派生线程，且无法恢复
- 如果 App Server 暂时返回空线程列表，活跃列表会回退读取当前项目已归属任务的本地 Codex session 元数据；回退读取只解析每个文件开头的有限元数据，并按工作区合并并缓存 10 秒，同时保留本地缓存中的当前活动线程作为恢复候选。新项目不会因该目录既有会话而出现旧任务；服务端有结果时始终以服务端为准，归档列表不使用此回退
- 归档、恢复和永久删除操作具备重复提交防护，线程状态通知会同步刷新活跃与归档列表；归档成功后会立即使旧的活跃列表刷新失效，且归档通知不会再从尚未更新的本地 session 元数据补回该任务
- 历史线程恢复会保留原 Provider，并防止过期刷新结果污染当前列表
- 恢复线程时加载用户消息、Codex 回复与命令输出到当前时间线
- 历史 turns 支持通过 `thread/turns/list` 分页补齐；未加载的 items 会按 turn 通过 `thread/items/list` 继续恢复，并展示计划、推理摘要、文件变更及工具事件；实时推理摘要会合并高频文本增量后再刷新界面，保持最终内容完整并减少连续重建
- 历史补齐失败会保留原线程时间线；超过安全页数时保留已加载内容并提示未完全加载
- 网页搜索、MCP/动态工具、图片、等待和审查模式会以专用历史事件卡片展示
- 提供真实 App Server 历史协议验证脚本，不创建任务或修改所选工作区文件

## 运行

开发与 CI 使用 Flutter 3.47.1（Dart 3.13.1）；项目最低 Dart 约束为 3.11.4。macOS 构建的最低系统版本为 macOS 12.0。

```bash
flutter run -d macos
```

Debug 与 Profile 构建使用独立的 `Codex Desk Development` Application Support 目录，Release 使用 `Codex Desk` 目录；三种构建均将偏好和加密密钥保存到各自目录中的本地存储文件。仅升级旧版 Release 时会尝试一次迁移 Keychain 值，迁移完成或跳过后不再访问 Keychain，因此不会因临时签名变化反复请求钥匙串授权。Release 与开发数据保持隔离。

应用使用已安装的 `codex` 命令。在“工作区”窗口点击“新建工作区”并选择主目录后，项目会先保存到列表；显式切换到该项目时才会自动连接运行时。之后可继续新建或切换其他工作区，也可为当前工作区添加多个附加目录。完成 Codex 登录后即可发起任务。界面不提供日常的运行时启动和停止操作。

### 运行时连接与恢复

Codex Desk 将 App Server 连接作为应用内部生命周期管理：启动时若恢复到有效工作区会自动连接；显式切换工作区、修改 Codex CLI 路径以及插件配置成功变更后，也会自动建立或重建连接。单纯新建项目只保存项目列表，不触发连接，也不会改写当前项目的旧版附加目录镜像，因此附加目录存储异常不会造成创建结果在内存与重启后不一致；附加目录的增删也不重启运行时，只会影响之后新建的任务。工作区列表保存在应用偏好中；从列表移除只会删除该记录，不会删除磁盘目录或对应的本地历史缓存。

运行时启动失败或进程意外退出时，应用会按 1 秒、2 秒、5 秒的有限退避最多自动重试三次，并在时间线显示等待和失败原因，避免持续重启。修复 CLI 或配置后，可在“Codex CLI”窗口重新检测以立即恢复连接。单个任务返回失败只会结束该任务并保留错误信息，不会把仍然可用的 App Server 连接标记为失败。

运行时启动、停止和应用退出使用连接代次隔离异步结果：已被替换或取消的旧启动流程不能回写新连接状态，进程若已创建则会立即回收。附加工作区目录使用不可变快照串行保存，连续增删时较慢的旧写入不会覆盖较新的目录集合。

### 安装到 Applications

在项目根目录运行以下脚本会在应用源码发生变化时构建 Release 版本；随后会先正常关闭正在运行的 Codex Desk、替换 `/Applications/Codex Desk.app`，再启动新版本。如果 macOS Automation 权限或应用状态导致正常退出请求被取消，脚本会静默回退，仅终止该安装包的进程后继续安装。升级旧版 Release 时应用可能进行一次 Keychain 数据迁移；仅当当前账户对 `/Applications` 没有写权限时，macOS 才会要求输入管理员密码。

```bash
./install_macos.sh
```

如需只构建、不安装或启动，可运行 `./install_macos.sh --build-only`。如需使用既有的 Release 构建重新安装而不重新编译，可运行 `./install_macos.sh --install-only`。

### 生成 DMG

以下命令会构建 Release 应用并生成未签名 DMG；不会启动应用。默认输出为 `dist/Codex-Desk-<version>.dmg`，版本来自 `pubspec.yaml`。

```bash
./build_dmg.sh
```

可使用 `./build_dmg.sh --output /absolute/path/Codex-Desk.dmg` 指定输出路径。提供 Developer ID 和已保存到 Keychain 的 `notarytool` profile 后，可直接生成签名、公证并装订的 DMG：

```bash
./build_dmg.sh \
  --sign-identity "Developer ID Application: Example (TEAMID)" \
  --notary-profile "codex-desk-notary"
```

也可通过 `CODEX_DESK_SIGN_IDENTITY` 与 `CODEX_DESK_NOTARY_PROFILE` 环境变量传入。脚本会依次执行 `codesign` 验证、Apple notarization、staple 验证和 Gatekeeper 评估。发布步骤及干净 macOS 安装回归见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)；当前仓库尚不包含 Apple Developer 证书或 notarization 凭据。

## App Server 历史验证

在有历史线程的工作区执行以下命令，可验证真实 App Server 的初始化、线程列表、恢复和全部 turns 分页协议；脚本不会创建任务、发送消息或修改工作区文件。

```bash
dart run tool/verify_app_server_history.dart --cwd /path/to/workspace
```

也可以用 `--thread-id <id>` 明确指定待验证的历史线程。若工作区暂无历史，脚本仅验证初始化与线程列表。

## 本地历史导入与导出

在线程区点击归档图标打开“本地历史”菜单，可执行以下操作：

- “导出本地历史”：将当前项目的线程列表、置顶状态、已缓存对话和文件 Diff 写入 JSON 文件。
- “导入到当前项目”：读取此前导出的 JSON，并替换当前项目在 Codex Desk 中的本地缓存。

导出文件不含 API Key、Keychain 内容或 Codex App Server 原始 session；但它包含对话文本和 Diff，文件本身为了可移植性未加密，请仅存放在可信位置。导入不会发送请求、恢复远端任务或修改项目文件；连接 App Server 后，服务端线程列表仍是权威来源。

## 运行时诊断

在侧栏点击“Codex CLI”可打开运行时窗口。窗口会重新探测当前 CLI，展示自动发现策略、解析到的可执行文件和版本；最近的 App Server stderr 与无法解析的协议行会以信息、警告或错误级别显示。使用“复制诊断”或“导出诊断”可生成包含运行状态、CLI 检测结果、`CODEX_HOME` 是否已配置以及最近日志的文本，适合贴到问题反馈中。导出时会再次生成脱敏文本，并仅写入你在系统文件选择器中指定的位置。

日志最多保留 200 条，重启本地运行时时会清空，且不会保存到历史缓存或项目文件。复制与展示前会完整隐藏 `Authorization: Bearer ...` 和 `Authorization: Basic ...` 凭据、`sk-` Key 以及 `api_key`、`token`、`secret`、`password` 等常见凭据字段；仍应在分享前自行检查诊断文本是否含有不希望公开的项目或环境信息。

## Git 项目视图

选择本地项目后，Codex Desk 会读取其 Git 工作区状态；点击侧栏“Git 项目”可手动刷新。视图显示当前分支（分离 HEAD 时显示 `DETACHED`）、暂存/未暂存/未跟踪改动数量，以及每个改动文件的状态和 Diff。未跟踪文件的 Diff 以 `/dev/null` 为基准预览；过大的 Diff 会被截断以避免占用过多内存。

Git 状态与 Diff 读取始终禁用 Shell。暂存、提交、推送和 PR 创建均只在用户点击相应操作后执行；还原文件改动会显示二次确认，推送不使用 force，提交也不会自动暂存文件。创建 PR 依赖本机已登录的 `gh` CLI。

## 安全边界

- 应用不保存自定义 Provider 的 Base URL 或 API Key，也不接受任意模型文本；这些内容由本地 Codex App Server 从 Codex 配置、环境变量或其认证存储读取。应用只保存用户从 App Server 模型目录中选择的模型 ID 与推理强度偏好。账户窗口临时提交的 OpenAI API Key 仅交给本地 Codex 运行时。
- 所有构建在 macOS Application Support 内的本地历史缓存仍使用 AES-GCM 加密，但密钥和偏好统一保存在应用专用的本地存储文件；升级旧版 Release 时仅尝试一次迁移原有 Keychain 值，之后不再访问 Keychain。任何能读取该用户目录的进程理论上都可能获取密钥，因此这不是面向多用户或高安全场景的存储方案。Debug/Profile 使用隔离的 `Codex Desk Development` 目录，Release 使用 `Codex Desk` 目录。手动导出的历史 JSON 为便于跨设备或备份恢复而保持明文，因此可能包含敏感对话和 Diff。
- App Server stderr 和协议诊断只会作为有上限的内存记录展示；不会进入历史缓存、项目文件或应用日志。运行时诊断复制内容会套用凭据脱敏规则，但任何诊断文本都应仅分享给可信对象。
- 运行时日志追加或清除时，设置中的诊断日志区域独立刷新，不会为日志变化重建无关工作区内容。
- Git 项目视图通过不使用 Shell 的受限 Git 子命令读取状态和 Diff；会显式读取全部未跟踪文件，不受用户 Git 的 `status.showUntrackedFiles` 配置影响。写入仓库或远端的操作只会在用户显式触发后执行；还原操作必须再次确认。
- 运行时只通过本机 `stdio` JSON-RPC 通信；不会启用远程 WebSocket。
- 审批默认请求批准；可在“变更与审批”切换为帮我批准，所选模式会在重启后恢复。帮我批准模式会直接允许命令、文件变更与额外权限请求，并在时间线留下记录。时间线仅在用户明确停留在最末端时自动跟随；刚从底部向上阅读不会被完成提醒、Composer 尺寸测量或延迟贴底回调拉回。Composer 上方的文件统计和活动提示只作展示，会让滚轮与触控板事件继续传给时间线。
- Codex App Server 按官方优先级解析 CLI 覆盖、受信任项目的 `.codex/config.toml`、选中的 profile、用户级 `$CODEX_HOME/config.toml`（默认 `~/.codex/config.toml`）、系统配置与内置默认值。本应用通过只读 `config/read` 获取最终生效的模型、Provider 和来源，不自行解析或覆盖 Provider 设置；“已读取”不代表凭据和网络已验证，仍需成功创建一次任务才能确认。修改外部配置后重新打开应用即可自动连接并读取最新值。
- 自定义 Provider 使用 `env_key` 时，对应环境变量必须对启动本应用的进程可见；也可使用 Codex 支持的其他认证来源。macOS 桌面构建不启用 App Sandbox，以便启动本机 `codex` 并读取其配置。运行时路径和本地历史加密密钥保存在应用专用的 Application Support 文件中。
- 插件管理会调用本机 `codex plugin` 子命令，并仅修改当前 Codex Home（优先 `CODEX_HOME`，否则 `~/.codex`）配置中相应插件的 `enabled` 状态；配置写入会串行化，并以同目录临时文件原子替换，且会保留 TOML 行尾注释；请只添加和安装可信来源的 marketplace 与插件。

## 开发约定

- 项目中的 Dart 方法均使用 Dartdoc 双语注释：先说明中文职责，再给出对应英文说明；公开方法还会说明重要的参数、返回值或副作用。
- 注释描述当前行为与边界，不记录实现过程；修改方法行为时，必须同步更新其双语注释与本 README。
- 双语注释的两种语言必须表达同一行为边界；协议名、字段名和快捷键保留原文，中文说明不擅自翻译这些稳定标识。English text must mirror the Chinese behavior and safety boundaries; protocol names, field names, and shortcuts stay unchanged.
- 新增的协调器、存储服务、文件预览和工作区面板均应在类型级与公开 API 级补充中文职责和英文对应说明；仅供实现细节使用的行内注释也应在修改时保持语义同步。
- 应用范围状态从 `codexControllerProvider` 读取，主题偏好从 `themePreferencesProvider` 读取；新页面和实时弹窗应优先使用 Riverpod 的 `ref.watch` / `ref.read`。`CodexController` 目前保留 `ChangeNotifier` 以桥接既有业务状态与异步服务，显式注入控制器仅用于测试或嵌入式场景；局部输入、悬停、拖拽、展开和滚动状态继续留在 Widget 内。
- 提交前依次运行 `dart format`、`flutter analyze` 与 `flutter test`；涉及 macOS 集成时，再运行 `flutter build macos --debug`。

### 本地 UI Kit

主题 Token 与 `YeknomWorkbenchTheme` 现维护在项目内的 `lib/src/theme/yeknom_workbench.dart`，避免依赖外部 UI Kit；桌面工具应复用该主题入口和 `YeknomPalette`，避免新增全局硬编码颜色。

### 持续集成

GitHub Actions 会在 macOS 上使用 Flutter 3.47.1 执行格式检查、`flutter analyze`、`flutter test`、原生 `RunnerTests` 和 macOS Debug 构建。UI Kit 由 `pubspec.lock` 固定 Git 提交，不需要 CI 访问开发机目录。

所有 `lib` 代码均由静态检查直接约束；项目不再通过整文件忽略 `unused_import`、`unnecessary_import`、`duplicate_import` 或 `use_key_in_widget_constructors` 来掩盖代码质量问题。
