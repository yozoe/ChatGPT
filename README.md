# Codex Desk

一个以 Flutter 构建的本地优先 Codex 桌面客户端。首个目标平台是 macOS。

后续开发任务、优先级与发布前置条件见 [ROADMAP.md](ROADMAP.md)；每项工作完成后会同步更新该清单和本文档。

已完成任务提醒的已查看状态会随对应工作区的加密历史缓存持久化；应用重启或侧栏重建后不会重复提醒，同一任务再次成功完成时会重新进入未查看状态。未查看的成功结果以任务行尾部的小蓝点提醒，包括完成时仍在当前会话中的任务；停止或取消的任务不会显示蓝点。点击对应任务行后清除，鼠标移入任务行时暂时隐藏并让位给快捷操作。切换或新建项目时不会带入上一项目的已查看状态。

平台支持范围与 Windows/Linux 评估见 [PLATFORM_SUPPORT.md](PLATFORM_SUPPORT.md)。

## 当前进度

- 已完成的命令、文件读取与工具调用会归组为默认折叠的活动摘要；连续命令之间的自动审批记录不再切断分组，点击摘要后仍可按原顺序查看命令与审批详情
- Flutter macOS 工程骨架
- 通过 `stdio` 启动 `codex app-server`
- JSON-RPC 初始化、创建线程、发起任务与中断任务的最小客户端
- 任务时间线与运行时状态界面
- App Server 因网络异常自动等待和重连时，会像 Codex 客户端一样在对应 turn 的对话时间线内逐次保留灰色 Wi-Fi 活动行 `Reconnecting... waiting for network`；当前任务直接显示，后台任务按 thread 暂存并在重新打开时归入自己的时间线，不会污染正在查看的会话。等待期间任务继续保持运行，不显示红色错误或手动操作，网络恢复后由 App Server 自动续接；已有后续进展或结束的等待记录会转为普通历史活动，不再作为实时辅助功能状态播报。只有 App Server 最终以 `turn/completed(status: failed)` 结束任务时，输入区上方才显示 Codex 风格的行内错误与“重试”入口；重试会在同一线程原样发送失败轮次的文字、结构化 Skill/图片输入、目标、计划模式与模型设置，不重复插入用户气泡，发送期间禁止重复点击。重试再次失败时入口继续保留；主动停止或取消不会出现重试。可重试输入只在当前应用进程和原工作区内存中保留，历史恢复不会臆造已丢失的提交上下文
- 应用共享状态由 Riverpod 管理：应用根部的 `ProviderScope` 同时持有 `CodexController` 与主题偏好，工作区和实时弹窗通过 Provider 订阅共享状态；页面临时交互状态仍保留在局部 `StatefulWidget`
- ChatGPT 浏览器登录与 OpenAI API Key 登录入口
- 命令、文件变更与额外权限的显式审批
- Provider、Base URL、凭据与默认模型均由本地 Codex App Server 按 Codex 配置层级直接读取；应用不再提供独立中转站输入。“Codex 配置”窗口展示当前项目最终生效的模型、Provider、字段来源和读取状态；输入框右下角的模型选择器可从 `model/list` 为后续新任务临时选模，也可随时恢复为“跟随配置”
- 当前工作区线程历史：列表、恢复、重命名、归档与归档视图恢复；任务行采用 4px 外边距、30px 树形文字缩进和稳定的 32px 高度，行尾运行指示器为 10px；普通任务行悬停时显示置顶和归档快捷图标，右键行可打开置顶、重命名、归档和永久删除菜单；任务首次显示后保持原有位置，运行、停止、完成或服务端更新时间变化只更新行内状态，不会重排任务，新发现任务追加到末尾；旧版 App Server 未附任务 ID 的完成事件也会通过权威列表正确结束当前或后台任务。当其他 Codex 客户端仍持有任务 writer 而恢复或归档被拒绝时，会在输入区上方显示非阻塞的“已在另一个应用中打开”提示和对应操作的重试入口，不弹出对话框，也不会写入当前任务时间线；批量归档会从冲突项起重试尚未处理的全部任务。已被另一客户端归档的任务不会直接恢复，而会提示先“取消归档”；取消归档后任务回到活跃列表，用户再自行打开。提示只在原工作区有效，切换项目后自动清除
- 侧栏任务标题过长时采用固定在任务气泡末端的 Codex 风格右侧透明渐隐裁切，不显示省略号；完整标题仍可通过任务行的悬停提示读取
- 用户消息气泡整体靠右；短消息会随内容收窄，长消息在最大宽度内从左边缘自然换行，避免续行贴右难以阅读；鼠标悬停在气泡上时，气泡下方会显示该条消息的本地时间
- 助手回复在会话时间线中直接显示 Markdown 正文，不再于每条回复左上方重复显示“Codex”身份标签；指向当前项目现有文件的链接会显示为带文件名和图标的紧凑文件行，缺失、越界或项目外目标仍保持普通链接并受原有安全边界限制；工具、审批、错误和系统记录的类型标题仍保留
- 文件行的解析结果只用于展示；点击、Markdown 预览读取和外部打开前都会按当前磁盘状态重新校验项目边界，文件被替换为越界符号链接时会拒绝打开。普通 Markdown 链接继续保留粗体、斜体、删除线、行内代码和链接图片等子样式；链接中的本地图片也只允许读取当前项目内目标，越界图片回退显示替代文本，图片 `alt` 会作为链接的读屏标签。助手身份不可见但会通过语义标签提供给读屏软件。异步文件行完成布局时，仅在用户仍停留于时间线底部且未开始滚动时继续贴底，包括文件行位于带横向滚动容器的 Markdown 表格内时
- 对话记录、线程列表与文件 Diff 会按本地项目加密缓存到 macOS Application Support；Release 构建的加密密钥仅保存在 macOS Keychain，开发构建使用隔离的本地开发存储；写入任一项目时会保留其他项目的缓存，并串行化并发写入；启动时先恢复缓存，连接 App Server 后再同步最新状态
- 项目列顶部的搜索图标会打开 Codex 风格的“搜索聊天”面板：可按任务标题、预览、所属项目或 Provider 搜索所有已加载项目的任务，选择后会先切换到所属项目再恢复任务；任务运行中仍可从该面板打开同项目任务，跨项目结果保持禁用以保护运行中的任务；面板还提供新聊天、打开文件夹和文件变更搜索的快捷入口。常用任务仍可置顶，置顶状态按本地项目保存并在重启后恢复
- 可从线程区的“本地历史”菜单导出或导入可移植 JSON：导入只替换当前项目的 Codex Desk 缓存，不会伪造或恢复 App Server 原始 session，也不会修改项目文件
- 可新建并保存多个工作区，左侧栏按创建顺序以项目节点展示，切换时顺序保持不变；当前项高亮，其他项可直接切换，完整路径收纳在项目详情卡片中，项目行不再额外弹出路径 tooltip，列表标题提供独立的“新建”和“管理”入口。控件 tooltip 与悬停详情卡片均需持续悬停 450ms 才会显示，避免快速掠过控件时干扰操作。系统临时目录根不能作为项目或附加目录，恢复时发现旧记录会自动清理。点击“新建”会打开 Codex 风格的创建项目弹窗，项目名称可选，源文件夹区域既可点击选择目录，也可直接拖入目录。每个项目拥有独立、稳定的任务归属，不以源目录的历史会话作为边界：新建项目总是从空任务列表开始，后续创建的任务只显示在所属项目中。每个工作区独立维护一个主目录、多个附加目录和本地历史，并自动恢复及清理失效路径，不向项目目录写入配置。升级至项目独立历史时会自动读取并迁移原目录索引的本地缓存，避免旧任务在重启后消失。新建、恢复或切换工作区后会自动连接运行时；客户端会在初始化握手中声明实验性 App Server 能力，以便通过 `runtimeWorkspaceRoots` 将附加目录授权给后续新任务。目录可随时增删，已有任务不受影响；悬停详情卡片使用紧凑字号展示项目名、任务数/路径和“编辑项目”入口
- 点击项目菜单中的“编辑”会打开接近 Codex 桌面端的项目编辑器：可修改项目显示名称、查看主源文件夹和附加源文件夹、添加或移除附加文件夹，并通过“移除本地项目”移除当前项目记录（不会删除磁盘目录或历史缓存）；项目名称输入框由单层外框承载，聚焦时不会叠加主题输入框边框；“保存”持久化项目名称和目录集合，“取消”只关闭编辑器
- 自动保存并恢复 macOS 主窗口的大小与位置；覆盖安装同一应用后仍会保留
- macOS Dock 图标保留带圆角的深色底板与橙色命令云，圆角外侧为真实透明像素，不含多余的无圆角黑色正方形；图形使用约 10% 的透明光学安全边距，使尺寸接近相邻 macOS 图标。Release/安装版由 bundle 的 `AppIcon` 原生渲染，`flutter run -d macos` 启动的 Debug 版会在插件初始化后采用同源 `DockIcon`，避免回退为 Flutter 默认图标
- 左侧导航采用 Codex 风格的项目树：工作区以文件夹节点展示，任务作为各项目下的文件缩进排列；选中任务使用紧凑的低对比圆角背景。常驻搜索框已移除，项目列顶部的搜索图标会打开独立的“搜索聊天”面板；面板搜索已加载项目的任务，并提供新聊天、打开文件夹和文件变更搜索快捷操作。每次启动都会读取全部项目的本地任务缓存并默认展开，只有点击项目行的展开/收起按钮才会改变本次会话中的显示状态，切换项目也不会收起其他项目。其他项目任务为只读预览，点击会先切换到所属项目并重连运行时再恢复，不能在当前项目中继续、置顶、归档、重命名或删除。置顶任务单独分组；每个运行中的任务在行尾显示高对比加载指示器，当前任务可点击保持焦点。刚创建但尚未进入服务端列表的任务也会先显示在侧栏；即使立即新建另一项任务，先前仍在启动的后台任务也会保留在列表中并持续显示运行状态。每次新的成功完成且尚未点击确认的任务都显示小蓝点，包括完成时仍在当前会话中的任务；鼠标移入任务行时蓝点暂时隐藏并让位给置顶、归档快捷操作，点击该任务行后清除；错误任务显示红色叹号。悬停项目会显示更多按钮和新建任务按钮，并自动展示项目详情卡片；运行中仍可点击“新对话”或另一个同项目任务，原任务会在后台继续执行并在完成后更新侧栏状态。打开运行中的后台任务会通过只读历史加载，不会重复申请 App Server writer，并仍可继续调整该任务方向；旧版运行时的无任务 ID 完成通知会通过任务列表对账清除对应后台状态。后台任务请求审批时，审批面板会明确标明其所属任务，避免误认为当前对话的操作。为避免终止后台任务，运行期间仍不能切换项目、重连运行时或修改插件；详情卡片可置顶项目并显示完整路径、当前项目或本地缓存中的任务数量，且每次打开都会刷新数量，置顶状态会持久化；点击更多显示置顶、编辑、创建永久工作树、归档聊天和移除项目菜单，点击新建任务按钮会清空当前任务并开始新任务
- “项目”标题下方提供 Codex 风格的紧凑文字入口：新对话、拉取请求、已安排和插件，入口文字采用 12px 辅助导航字号。后三项会切换右侧为独立工作区，而不是弹窗；从这些工作区点击侧栏“新对话”、项目行“新建任务”或搜索面板“新聊天”时，都会统一返回会话工作台并清空当前任务。拉取请求提供 GitHub CLI 安装提示、复制命令与现有 Git 项目工作流入口；已安排提供搜索、推荐模板、创建与取消本地定时任务；插件页可在“插件 / 技能”间切换，分别展示本机 CLI 插件和当前项目从 App Server 读取的可用技能。插件页右上角的设置按钮会打开 Codex 风格的“插件 / MCP / 技能”管理弹层，三个标签显示真实数量并提供各自搜索；已安装插件、`codex mcp list --json` 返回的服务器和 App Server 技能均可在列表中启停，MCP 栏还可添加 HTTP 服务器并查看连接详情。插件页右上角的“添加”菜单可创建插件、添加 marketplace 或录制技能：创建插件会开启新对话并预填 `$plugin-creator`，录制技能会开启新对话且直接启用结构化“录制技能”上下文；市场表单只接受 GitHub 仓库、Git URL 或本地目录，Git 引用沿用 marketplace 的 CLI 默认设置。已安排任务会把提示词和执行时间安全地保存在应用偏好中，到点后自动切换回对应项目、创建新对话并发送。定时任务只会在 Codex Desk 正在运行时执行；重启会保留待执行项，若当前任务仍在运行或运行时不可用则每分钟重试，不会抢占用户正在执行的任务
- 取消已安排任务会同时撤销等待中的项目切换或运行时重连；已取消任务不会在后台继续创建对话或发送提示词。
- 工作区采用左右两列主结构：左侧“项目”列与右侧“工作台”列各自拥有独立顶部栏，避免全局顶部栏跨越任务导航；当前任务名称、Provider / App Server、沙箱边界和文件变更入口位于工作台顶部。当前任务名称可点击行内编辑，Enter 保存、Esc 取消；未创建任务时显示“新建任务”。宽屏下环境信息继续作为右侧工作台内的辅助检查区，左侧任务栏和右侧环境栏仍可在最小/最大宽度范围内通过细分隔条调整，窄窗口自动收起环境栏
- 对话时间线采用扁平消息样式，不使用补间滚动动画；新建任务时只保留内置欢迎项，不会把上一个历史任务的首条用户消息带入空白对话。仅在用户仍停留在底部附近时跟随后续更新，主动上滑阅读后会保留当前位置，即使任务已结束或滚底回调已在上一帧排队，也会在执行前重新确认跟随状态，不会因普通状态刷新被拉回底部。首次切换任务时显示 Codex 风格历史加载页，加载完成后缓存最近 8 个已打开任务的完整时间线页面及其滚动位置；再次切换直接显示已保活页面，不播放平滑滚动或重新定位动作；超出上限的较早任务会重新读取历史。历史读取失败时不会显示前一任务内容。Codex 回复按 GitHub Flavored Markdown 渲染，支持标题、列表、加粗、链接、引用、表格与代码块，且正文仍可选择复制；HTTP、HTTPS 和邮件链接继续交由系统应用打开，当前项目内的 `.md` / `.markdown` 相对或绝对链接会在覆盖工作台的阅读器中直接显示格式化内容。阅读器支持预览与可选择复制的源码模式、项目内 Markdown 相对链接导航、本地图片、返回、`Esc` 关闭和“在默认应用中打开”；`文件:行号` 与 `文件:行号:列号` 会保留定位信息并在源码模式高亮对应行。预览文件上限为 8 MB，源码模式会截断显示超过 4096 个字符的单行并保留长度提示，避免超宽布局；远程图片不会自动请求。其他项目内文件仍交由系统默认应用打开；所有本地目标都会解析符号链接并限制在当前项目目录内，缺失或越界时显示失败提示。文本选择由时间线外层统一处理，不创建会抢占滚轮的嵌套文字滚动区；用户输入、命令和系统记录保持纯文本。连续的历史命令、文件读取与工具调用会收纳为默认折叠的 Codex 风格活动清单，点击标题可展开或收起，完整事件详情仍通过条目提示保留。运行中的命令会以一条可复制、可截断的“正在运行”状态行显示，完成后归入该活动清单；无命令执行时则以更明亮、较快扫光与三点呼吸节奏的“正在思考”行表示当前任务仍在处理，任务结束后会自动移除；系统要求减少动态效果时该提示保持静止；每个结束的任务会在时间线中保留“耗时”记录，存在执行明细时可展开或收起，其中“已运行了命令”等嵌套活动摘要默认折叠，只有点击后才显示明细。恢复历史时以 App Server 命令项为准，并按命令项 ID 补回服务端未返回的本地已完成命令。非当前任务或未打开任务收到的迟到/后台事件只刷新任务列表，不会改变当前时间线、命令或计划；切换任务后的停止请求结果及无任务 ID 的旧版完成通知同样不会写入新任务。Enter 发送消息，Shift+Enter 换行；输入法仍有未确认的组合文字时，Enter 仅交由输入法取消或确认组合，不会发送消息；即使平台先清除组合范围再派发候选确认的 Enter，也不会误发送，组合确认后的后续 Enter 可正常发送。App Server 的命令输出增量等高频协议事件不会显示为对话消息；需要决策的审批、任务结果和恢复历史中的实际命令记录仍会保留
- 会话时间线只在任务时长状态下方保留分割线，包括运行中的“已处理 X 秒”和完成后可展开的“耗时”；其他消息、活动和系统记录之间使用等高空白间距，不再绘制分割线。
- 任务完成后的“耗时”展开按钮使用无描边文字与箭头，保留圆角点击反馈和下方分割线。
- 运行中任务会根据 App Server 的 `turn/plan/updated` 通知悬浮展示结构化步骤，区分待执行、进行中与已完成状态，并显示当前“第 N / M 步”；任务结束后自动收起
- 对话末尾会优先使用 App Server 的实时事件显示实际执行阶段：只有单一且明确的结构化 `commandActions` 才会区分“正在读取 文件名”“正在搜索 查询词 · 目标文件夹”“正在列出…文件夹中的文件”和“正在编辑文件”；包含读取与构建、测试等多个动作的复合命令会回退显示“正在运行 具体命令”，不会被首个文件动作掩盖。推理项收到 `item/reasoning/summaryTextDelta` 后会显示 Codex 提供的具体分析摘要，例如 `Planning…`、`Clarifying…` 或 `Inspecting…`，而不是始终停留在笼统的“正在分析”；摘要更新只作用于匹配的当前推理项，迟到事件不会覆盖后续命令。计划整理、撰写回复、网页搜索/打开/页内查找、MCP/动态/协作工具调用、图片处理、等待、上下文压缩和审查也保留对应状态；动态技能读取会显示具体技能名，例如“正在读取 Code Review 技能”。技能读取完成后会在原会话位置保留“已读取…技能”记录；子代理以紧凑状态徽标展示，按 App Server 的子线程标识从“已开始工作”原位更新到“已完成”、失败或停止，并随加密历史与服务端线程历史恢复。服务端报告未知的新操作类型时显示中性的“正在执行操作”，仅在没有活动事件时显示“正在思考”兜底提示。其他实时状态在对应 item 或任务结束后自动清除，工具活动与上下文压缩继续随线程历史恢复
- “正在思考”、正在运行命令及所有已识别的实时活动状态共用低干扰扫光动画；系统要求减少动态效果时保持静止。
- 任务运行中会在本轮用户消息之后固定显示按秒更新的“已处理”时长，后续流式回复、文件操作和实时活动继续排列在其下方；计时器不会随最新活动移动到时间线底部，并会在应用暂停后按真实起始时间纠偏。计时文本可由辅助技术查询，但不会每秒打断式播报。完成后替换为“耗时”记录；只有存在执行明细时才可展开或收起。折叠区只包含推理、状态、命令与工具等执行过程，命令和工具保持紧凑活动清单，最终回复、审批与错误始终外显并保持原始时间顺序。
- 运行中任务可在 Composer 中连续按 Enter 提交多条非持久化的待发送方向；它们按提交顺序堆叠在 Composer 顶部操作栏，超过自适应最大高度后在栏内滚动，不会挤出输入框。每条都可独立点击“调整方向”或删除；方向发送保持串行，发送期间其余发送操作暂时禁用。暂存期间消息不进入会话气泡；通过 App Server `turn/steer` 接受后会连同图片显示在当前会话中，即使接受响应晚于任务完成通知，也会按实际发送位置排列在“任务完成”之前，不会丢失图片或提前清理临时文件；等待接受期间切走再切回同一任务时会以重载后的历史为准，不会用旧位置重复插入方向。该交互不会弹出二次编辑器或创建新线程。运行中仍可附加文件、图片、文件夹、技能、目标和计划上下文；停止按钮会携带当前线程与 turn 标识中断任务，并仅在已取得活动 turn 后显示为与发送按钮一致的 36px 圆形点击面
- 存在文件变更时，输入框顶缘会悬浮显示紧凑统计提示，例如“1 个文件已更改 +15 -20”；提示不占用独立布局高度，统计复用文件 Diff；Diff 缺失、仅含元数据或无法逐行计数时显示 `+? -?`，不以 `+0 -0` 伪装未知结果
- 底部输入区采用深色圆角工作台样式，集中展示任务状态、审批模式、模型与推理强度，并会随窗口宽度折叠次要工具项；默认输入文字为 13px，发送按钮为 36px 圆形，上箭头保持居中。随心输入、模型选择和推理强度控件不绘制额外边框，推理强度直接显示“默认”“高”“中”“低”等强度名称
- 输入区“添加”菜单支持附加文件、图片和文件夹路径，显式附加当前项目，设置线程目标，切换计划模式，录制技能，以及从 App Server 动态选择项目可用技能；也可把文件或文件夹直接拖入输入卡片，在 Finder 中复制后通过 `Command+V` / `Control+V` 粘贴，或直接粘贴剪贴板中的屏幕截图；图片附件会显示缩略图，点击后以 Codex 风格沉浸式预览覆盖工作台，缩放百分比按图片原始像素和当前画布计算，按钮缩放会保留当前查看中心，并支持手势、键盘 `+` / `-`、双击切换原始/两倍比例、`Command+0` / `Control+0` 复位及 `Esc` 关闭，右上角可交由默认图片应用继续处理或另存副本；普通文本剪贴板仍按当前光标或选区粘贴；图片、目标、计划模式和技能分别通过 Codex 原生结构化协议发送
- 随任务发送的图片会在对话时间线的用户消息气泡中保留本地缩略图，点击后复用 Composer 图片相同的沉浸式预览、缩放、默认应用打开和另存副本操作；剪贴板生成的临时图片由会话控制器接管，只要仍被 Composer、当前/缓存时间线、排队方向、运行中提交或失败重试引用，就不会因任务完成、切换功能页、Composer 重建或控制器切换而提前删除；最后引用消失时即使 Composer 未挂载也会主动清理，控制器释放时则兜底清理；历史缓存会记录图片路径，图片文件不可用时仅隐藏缩略图，不影响文本消息
- 主题系统已内置于项目；顶部“主题”按钮可切换跟随系统、浅色或深色模式，以及八套兼容预设。默认深色主题采用 Codex 风格的石墨黑工作台、12–13px 紧凑正文、分级灰色文字和 15–17px 的轻量功能图标；蓝色激活、绿色成功与红色错误语义色会随主题同步切换
- 文件变更不会逐条显示在会话中；每轮任务完成后会在对话区显示仅属于该轮的汇总卡片，列出文件数与新增/删除行数，并通过“审核”打开只读代码审查窗口；下一轮开始时清空上一轮摘要，若启动失败则恢复，历史任务也只恢复最后一轮的文件集合。“审核”左侧的“撤销”会在完整、未截断的任务 Diff 可用且当前项目没有任何前台或后台任务运行时，由 Git 解析并核对补丁路径与摘要文件列表，再检查当前文件是否仍与原始 Diff 精确匹配，最后反向应用本轮改动；撤销期间同时禁止发送新任务和重复点击。若目标文件已有暂存改动、文件随后又被修改、路径不一致或 Diff 不完整，撤销保持禁用或失败并保留现有文件与摘要，不会回退整个 Git 工作区、遗留已暂存改动或覆盖任务前已有改动。悬停单个已编辑文件时会显示跟随窗口边界自适应的紧凑 Diff 预览，按 unified Diff hunk 展示实际行号，并在 Diff 异步补齐或更新时同步刷新；窗口支持按文件查看逐行 Diff、长行横向滚动和完整任务 Diff，不提供提交或推送操作。若 App Server 未携带文件级 Diff，应用会对未跟踪文件从 Git 工作区安全补齐；无法可靠取得 Diff 时显示未知统计，不伪装成 `+0 -0`
- 文件变更摘要卡片的标题使用 14px 半粗体，新增/删除行统计使用 13px 字号，避免在对话流中显得过大。
- 右侧检查器采用 Codex 风格的“环境信息”圆角卡片：展示本地 Git 变更、当前分支、提交/推送、创建拉取请求和比较分支入口；标题使用 15px，操作行和分组标题使用 13px，文件行使用 13px，保持紧凑的信息密度；文件变更仍以可展开行列出本次任务完整 Diff 和 AI 修改的文件
- 模型与推理强度选项由 Codex App Server 动态提供；模型气泡不显示额外图标，跟随配置简化显示为“默认”，其他模型只显示展示名称并隐藏内部模型 ID；推理强度会随所选模型联动并保存，控件只显示强度名称，两者只用于后续新建任务，不覆盖恢复的历史任务
- 运行中连续提交的“调整方向”会按序暂存在输入框顶缘；未手动调整时，当前任务及后续轮次每次结束都会取队首作为同一线程的下一轮任务发送。自动续发失败时会恢复原队列且不留下伪造的用户消息；手动调整恰逢任务结束且 `turn/steer` 未成功时也会安全转为下一轮发送，只有逐条点击删除才会丢弃
- 活跃与归档线程列表会跟随 App Server 分页加载，不限于首 50 条
- 提供“插件”管理入口：读取本机 Codex CLI 的已安装与可安装插件、当前项目目录下生效的 MCP 服务器以及 App Server 技能，支持添加本地或远程 marketplace、刷新 Git marketplace、安装插件、确认后卸载插件，以及原子启停插件、MCP 与技能；配置成功后会自动重连运行时并更新生效状态。MCP 列表会标注用户、项目或托管范围：用户服务器写回 `~/.codex/config.toml`（或当前 `CODEX_HOME`），项目服务器只在 Codex 已信任当前项目时才识别并写回项目 `.codex/config.toml`，未受信任项目的同名配置不会覆盖用户级来源，无法识别配置来源的托管服务器保持只读；MCP 名称、项目信任路径与技能路径配置兼容 TOML 双引号和单引号键/字符串，启停时保留原有单引号写法且不会追加重复配置块；切换项目会清空旧列表并丢弃仍在途的旧项目刷新结果，扩展配置写入期间禁止切换主项目。插件、MCP、技能和添加服务器失败均会在当前界面显示原因；如果配置已写入而后续列表刷新失败，界面会关闭添加窗口并单独显示刷新警告，不会误导用户重复添加。插件管理会复用运行时自动发现的 CLI 绝对路径，不依赖桌面应用的 `PATH`，路径解析和每条 CLI 命令均会在 20 秒后超时；插件会展示安装策略与认证时机，OAuth/连接器授权仍由 Codex Host 在安装或首次使用时处理
- “Codex CLI”运行时窗口会展示 CLI 自动发现来源、版本与最近 stderr/协议诊断日志；日志仅在内存中保留最近 200 条，可一键复制脱敏诊断报告，不会写入对话历史
- 侧栏“Git 项目”提供当前分支、暂存/未暂存/未跟踪改动摘要、按路径搜索和状态筛选的文件列表与 Diff；可对单个文件暂存或经确认后还原，随后可显式提交、推送或通过本机已登录的 GitHub CLI 创建拉取请求；超大 Diff 会明确提示仅显示前 120,000 个字符
- 线程列表支持批量归档；单个活跃或归档线程可在二次确认后永久删除，删除会同时移除 App Server 定义的派生线程，且无法恢复
- 如果 App Server 暂时返回空线程列表，活跃列表会回退读取当前项目已归属任务的本地 Codex session 元数据；回退读取只解析每个文件开头的有限元数据，并按工作区合并并缓存 10 秒，同时保留本地缓存中的当前活动线程作为恢复候选。新项目不会因该目录既有会话而出现旧任务；服务端有结果时始终以服务端为准，归档列表不使用此回退
- 归档、恢复和永久删除操作具备重复提交防护，线程状态通知会同步刷新活跃与归档列表；归档成功后会立即使旧的活跃列表刷新失效，且归档通知不会再从尚未更新的本地 session 元数据补回该任务
- 历史线程恢复会保留原 Provider，并防止过期刷新结果污染当前列表
- 恢复线程时加载用户消息、Codex 回复与命令输出到当前时间线
- 历史 turns 支持通过 `thread/turns/list` 分页补齐；未加载的 items 会按 turn 通过 `thread/items/list` 继续恢复，并展示计划、推理摘要、文件变更及工具事件；实时推理摘要会合并高频文本增量后再刷新界面，保持最终内容完整并减少连续重建
- 历史补齐失败会保留原线程时间线；超过安全页数时保留已加载内容并提示未完全加载
- 网页搜索、MCP/动态工具、图片、等待和审查模式会以专用历史事件卡片展示
- 提供真实 App Server 历史协议验证脚本，不创建任务或修改所选工作区文件

## 运行

开发与 CI 使用 Flutter 3.47.1（Dart 3.13.1）；项目最低 Dart 约束为 3.11.4。macOS 构建的最低系统版本为 macOS 12.0。

```bash
flutter run -d macos
```

Debug 与 Profile 构建使用独立的 `Codex Desk Development` Application Support 目录保存开发偏好和缓存，不访问 macOS Keychain，避免临时签名变化导致每次 `flutter run` 重复请求钥匙串密码。Release 构建仍使用 Keychain，并与开发数据隔离。

应用使用已安装的 `codex` 命令。在“工作区”窗口点击“新建工作区”并选择主目录后会自动连接运行时；之后可继续新建并切换其他工作区，也可为当前工作区添加多个附加目录。完成 Codex 登录后即可发起任务。界面不提供日常的运行时启动和停止操作。

### 运行时连接与恢复

Codex Desk 将 App Server 连接作为应用内部生命周期管理：启动时若恢复到有效工作区会自动连接；新建或切换工作区、修改 Codex CLI 路径以及插件配置成功变更后，也会自动建立或重建连接。附加目录的增删不重启运行时，只会影响之后新建的任务。工作区列表保存在应用偏好中；从列表移除只会删除该记录，不会删除磁盘目录或对应的本地历史缓存。

运行时启动失败或进程意外退出时，应用会按 1 秒、2 秒、5 秒的有限退避最多自动重试三次，并在时间线显示等待和失败原因，避免持续重启。修复 CLI 或配置后，可在“Codex CLI”窗口重新检测以立即恢复连接。单个任务返回失败只会结束该任务并保留错误信息，不会把仍然可用的 App Server 连接标记为失败。

运行时启动、停止和应用退出使用连接代次隔离异步结果：已被替换或取消的旧启动流程不能回写新连接状态，进程若已创建则会立即回收。附加工作区目录使用不可变快照串行保存，连续增删时较慢的旧写入不会覆盖较新的目录集合。

### 安装到 Applications

在项目根目录运行以下脚本会在应用源码发生变化时构建 Release 版本；随后会先正常关闭正在运行的 Codex Desk、替换 `/Applications/Codex Desk.app`，再启动新版本。如果 macOS Automation 权限或应用状态导致正常退出请求被取消，脚本会静默回退，仅终止该安装包的进程后继续安装。若源码未变，则会重启已安装版本，避免临时签名重新覆盖后重复触发 macOS Keychain 授权。仅当当前账户对 `/Applications` 没有写权限时，macOS 才会要求输入管理员密码。

```bash
./install_macos.sh
```

如需只构建、不安装或启动，可运行 `./install_macos.sh --build-only`。如需使用既有的 Release 构建重新安装而不重新编译，可运行 `./install_macos.sh --install-only`。

### 生成 DMG

以下命令会构建 Release 应用并生成未签名 DMG；不会启动应用。默认输出为 `dist/Codex-Desk-<version>.dmg`，版本来自 `pubspec.yaml`。

```bash
./build_dmg.sh
```

可使用 `./build_dmg.sh --output /absolute/path/Codex-Desk.dmg` 指定输出路径。提供 Developer ID 和已保存到 Keychain 的 `notarytool` profile 后，可直接生成签名、公证并装订的 DMG：

```bash
./build_dmg.sh \
  --sign-identity "Developer ID Application: Example (TEAMID)" \
  --notary-profile "codex-desk-notary"
```

也可通过 `CODEX_DESK_SIGN_IDENTITY` 与 `CODEX_DESK_NOTARY_PROFILE` 环境变量传入。脚本会依次执行 `codesign` 验证、Apple notarization、staple 验证和 Gatekeeper 评估。发布步骤及干净 macOS 安装回归见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)；当前仓库尚不包含 Apple Developer 证书或 notarization 凭据。

## App Server 历史验证

在有历史线程的工作区执行以下命令，可验证真实 App Server 的初始化、线程列表、恢复和全部 turns 分页协议；脚本不会创建任务、发送消息或修改工作区文件。

```bash
dart run tool/verify_app_server_history.dart --cwd /path/to/workspace
```

也可以用 `--thread-id <id>` 明确指定待验证的历史线程。若工作区暂无历史，脚本仅验证初始化与线程列表。

## 本地历史导入与导出

在线程区点击归档图标打开“本地历史”菜单，可执行以下操作：

- “导出本地历史”：将当前项目的线程列表、置顶状态、已缓存对话和文件 Diff 写入 JSON 文件。
- “导入到当前项目”：读取此前导出的 JSON，并替换当前项目在 Codex Desk 中的本地缓存。

导出文件不含 API Key、Keychain 内容或 Codex App Server 原始 session；但它包含对话文本和 Diff，文件本身为了可移植性未加密，请仅存放在可信位置。导入不会发送请求、恢复远端任务或修改项目文件；连接 App Server 后，服务端线程列表仍是权威来源。

## 运行时诊断

在侧栏点击“Codex CLI”可打开运行时窗口。窗口会重新探测当前 CLI，展示自动发现策略、解析到的可执行文件和版本；最近的 App Server stderr 与无法解析的协议行会以信息、警告或错误级别显示。使用“复制诊断”或“导出诊断”可生成包含运行状态、CLI 检测结果、`CODEX_HOME` 是否已配置以及最近日志的文本，适合贴到问题反馈中。导出时会再次生成脱敏文本，并仅写入你在系统文件选择器中指定的位置。

日志最多保留 200 条，重启本地运行时时会清空，且不会保存到历史缓存或项目文件。复制与展示前会完整隐藏 `Authorization: Bearer ...` 和 `Authorization: Basic ...` 凭据、`sk-` Key 以及 `api_key`、`token`、`secret`、`password` 等常见凭据字段；仍应在分享前自行检查诊断文本是否含有不希望公开的项目或环境信息。

## Git 项目视图

选择本地项目后，Codex Desk 会读取其 Git 工作区状态；点击侧栏“Git 项目”可手动刷新。视图显示当前分支（分离 HEAD 时显示 `DETACHED`）、暂存/未暂存/未跟踪改动数量，以及每个改动文件的状态和 Diff。未跟踪文件的 Diff 以 `/dev/null` 为基准预览；过大的 Diff 会被截断以避免占用过多内存。

Git 状态与 Diff 读取始终禁用 Shell。暂存、提交、推送和 PR 创建均只在用户点击相应操作后执行；还原文件改动会显示二次确认，推送不使用 force，提交也不会自动暂存文件。创建 PR 依赖本机已登录的 `gh` CLI。

## 安全边界

- 应用不保存自定义 Provider 的 Base URL 或 API Key，也不接受任意模型文本；这些内容由本地 Codex App Server 从 Codex 配置、环境变量或其认证存储读取。应用只保存用户从 App Server 模型目录中选择的模型 ID 与推理强度偏好。账户窗口临时提交的 OpenAI API Key 仅交给本地 Codex 运行时。
- Release 构建在 macOS Application Support 内的本地历史缓存会用 Keychain 密钥加密；Debug 与 Profile 构建的密钥和缓存位于隔离的 `Codex Desk Development` 目录，不应作为安全存储。手动导出的历史 JSON 为便于跨设备或备份恢复而保持明文，因此可能包含敏感对话和 Diff。
- App Server stderr 和协议诊断只会作为有上限的内存记录展示；不会进入历史缓存、项目文件或应用日志。运行时诊断复制内容会套用凭据脱敏规则，但任何诊断文本都应仅分享给可信对象。
- Git 项目视图通过不使用 Shell 的受限 Git 子命令读取状态和 Diff；会显式读取全部未跟踪文件，不受用户 Git 的 `status.showUntrackedFiles` 配置影响。写入仓库或远端的操作只会在用户显式触发后执行；还原操作必须再次确认。
- 运行时只通过本机 `stdio` JSON-RPC 通信；不会启用远程 WebSocket。
- 审批默认请求批准；可在“变更与审批”切换为帮我批准，所选模式会在重启后恢复。帮我批准模式会直接允许命令、文件变更与额外权限请求，并在时间线留下记录。
- Codex App Server 按官方优先级解析 CLI 覆盖、受信任项目的 `.codex/config.toml`、选中的 profile、用户级 `$CODEX_HOME/config.toml`（默认 `~/.codex/config.toml`）、系统配置与内置默认值。本应用通过只读 `config/read` 获取最终生效的模型、Provider 和来源，不自行解析或覆盖 Provider 设置；“已读取”不代表凭据和网络已验证，仍需成功创建一次任务才能确认。修改外部配置后重新打开应用即可自动连接并读取最新值。
- 自定义 Provider 使用 `env_key` 时，对应环境变量必须对启动本应用的进程可见；也可使用 Codex 支持的其他认证来源。macOS 桌面构建不启用 App Sandbox，以便启动本机 `codex` 并读取其配置。运行时路径和本地历史加密密钥仍使用标准 macOS Keychain 保存。
- 插件管理会调用本机 `codex plugin` 子命令，并仅修改当前 Codex Home（优先 `CODEX_HOME`，否则 `~/.codex`）配置中相应插件的 `enabled` 状态；配置写入会串行化，并以同目录临时文件原子替换，且会保留 TOML 行尾注释；请只添加和安装可信来源的 marketplace 与插件。

## 开发约定

- 项目中的 Dart 方法均使用 Dartdoc 双语注释：先说明中文职责，再给出对应英文说明；公开方法还会说明重要的参数、返回值或副作用。
- 注释描述当前行为与边界，不记录实现过程；修改方法行为时，必须同步更新其双语注释与本 README。
- 应用范围状态从 `codexControllerProvider` 读取，主题偏好从 `themePreferencesProvider` 读取；新页面和实时弹窗应优先使用 Riverpod 的 `ref.watch` / `ref.read`。`CodexController` 目前保留 `ChangeNotifier` 以桥接既有业务状态与异步服务，显式注入控制器仅用于测试或嵌入式场景；局部输入、悬停、拖拽、展开和滚动状态继续留在 Widget 内。
- 提交前依次运行 `dart format`、`flutter analyze` 与 `flutter test`；涉及 macOS 集成时，再运行 `flutter build macos --debug`。

### 本地 UI Kit

主题 Token 与 `YeknomWorkbenchTheme` 现维护在项目内的 `lib/src/theme/yeknom_workbench.dart`，避免依赖外部 UI Kit；桌面工具应复用该主题入口和 `YeknomPalette`，避免新增全局硬编码颜色。

### 持续集成

GitHub Actions 会在 macOS 上使用 Flutter 3.47.1 执行格式检查、`flutter analyze`、`flutter test` 和 macOS Debug 构建。UI Kit 由 `pubspec.lock` 固定 Git 提交，不需要 CI 访问开发机目录。
