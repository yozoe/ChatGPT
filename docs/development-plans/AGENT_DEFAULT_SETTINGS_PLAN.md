# 智能体默认设置开发计划

> 状态：待开发。本文档根据 Codex 官方客户端设置截图整理，当前项目尚未完整实现其中的配置能力。

## 目标

在 Codex Desk 的“配置”工作区中，对齐官方客户端的“智能体默认设置”信息层级和真实行为：

- 批准策略（Approval policy）
- 沙盒设置（Sandbox）
- 网页搜索（Web search）
- 输出详细程度（Verbosity）
- 推理摘要（Reasoning summaries）
- 用户配置与 `config.toml` 入口

界面可以接近官方客户端，但只有 App Server 或 Codex CLI 明确支持的字段才能提供可编辑控件；不支持的能力必须显示真实的“由配置管理”或“模型默认”。

本计划只覆盖截图中的“智能体默认设置”卡片。截图下方的“模型功能”只复用当前已有的模型、Provider 和推理强度状态；模型目录、Provider 管理、凭据和 Base URL 不在本计划内。

## 当前项目基础

| 能力 | 当前实现 | 计划差距 |
| --- | --- | --- |
| 批准策略 | `ApprovalMode` 支持“请求批准 / 帮我批准”，并保存到本地 | 官方 Schema 已提供 `untrusted`、`on-request`、`never` 及 granular 形式；需要建立映射，不能把“帮我批准”直接等同于 `never` |
| 沙盒 | 设置页显示“由配置管理” | 官方 Schema 已提供 `read-only`、`workspace-write`、`danger-full-access`；尚未读取或编辑最终生效值 |
| 网页搜索 | 时间线可显示网页搜索活动；浏览器有独立启用开关 | 官方 Schema 已提供 `disabled`、`cached`、`indexed`、`live`；尚未作为默认设置暴露，不能与内置浏览器混用 |
| 输出详细程度 | 设置页显示“模型默认” | 官方 Schema 已提供 `low`、`medium`、`high`；尚未读取或发送 verbosity 配置 |
| 推理摘要 | 已接收并渲染运行时摘要 | 官方 Schema 已提供 `auto`、`concise`、`detailed`、`none`；尚未实现偏好控制 |
| 用户配置 | 已通过 App Server `config/read` 读取模型、Provider 和来源；设置页可查看状态 | 需要扩展非敏感字段映射、配置 profile 语义和打开 `config.toml` 的明确入口 |

当前项目已经具备配置读取基础：`CodexAppServer.readConfig()` 调用 `config/read`（`includeLayers: false`），控制器从返回的 `config` 和 `origins` 提取模型、Provider 及来源。官方 0.154.0-alpha Schema 还明确提供 `config/value/write`、`config/batchWrite` 和上述设置字段；后续应在这个边界上增量扩展。由于项目当前基线仍是 0.153.4，必须先验证旧运行时对字段和写入方法的兼容性；若响应未提供某字段，必须保留只读降级，不从本地活动或提示词推断。

官方 App Server 在隔离空配置中会返回这些字段但值为 `null`；这表示“继承运行时/模型默认值”，不能被解析为“不支持”。因此配置快照模型必须区分“字段缺失”“字段存在且为 null”和“字段存在且有值”三种状态。

现有配置回归测试只覆盖模型、Provider、来源和项目切换清理；尚未覆盖上述智能体默认设置字段，因此阶段一必须先补充协议响应 fixture 与字段缺失/类型错误测试。

### 协议兼容矩阵

| 字段/动作 | 官方 0.154.0-alpha Schema | 项目当前 0.153.4 基线 | 实施要求 |
| --- | --- | --- | --- |
| `config/read` 的 `config` / `origins` | 已确认 | 已接入模型、Provider 和来源 | 扩展字段解析，并对缺失字段只读降级 |
| `config/value/write` | 已确认 | 尚未接入 | 先探测方法和响应，失败时不改变 UI 值 |
| `config/batchWrite` | 已确认 | 尚未接入 | 使用 `edits`、`expectedVersion` 和 `replace`/`upsert` 策略进行原子批量编辑，避免部分写入 |
| `reloadUserConfig` | 已确认 | 尚未确认 | 仅在运行时接受时使用；不能假设模型/推理强度等 session-static 值会热加载 |
| `approval_policy` | 已确认 | 尚未确认字段兼容性 | 映射前先验证字符串和 granular 对象两种编码 |
| `sandbox_mode` / `web_search` / `model_verbosity` / `model_reasoning_summary` | 已确认 | 尚未确认字段兼容性 | 运行时不支持时保持“由配置管理”，不得发送未知字段 |

目标运行时升级到包含上述 Schema 的版本后，才可将对应行从“只读/待补证”切换为可编辑；版本探测本身也必须进入运行时诊断，便于解释降级原因。

### 设置作用域

默认值与当前线程运行状态必须分开。除非协议明确支持热更新，设置变更只影响后续新任务，不得中断或修改正在运行的 turn。

| 设置 | 推荐作用域 | 是否影响运行中任务 | 默认来源 |
| --- | --- | --- | --- |
| 批准策略 | 用户级默认值 | 否；只影响后续审批请求 | Codex Desk 本地偏好，必要时受组织策略限制 |
| 沙盒设置 | 用户/项目配置，按最终配置来源决定 | 否；下一次任务启动时生效 | `config.toml`、项目配置或运行时参数 |
| 网页搜索 | 用户级默认值或运行时配置 | 否；下一次任务生效 | Codex 配置或 App Server 能力 |
| 输出详细程度 | 用户级或模型级默认值 | 否；下一次任务生效 | 模型/Provider 配置 |
| 推理摘要 | 模型/运行时能力 | 通常只读 | App Server 与模型协商结果 |

项目切换时必须重新读取项目相关的最终配置，但不能把全局用户默认值复制成项目专属值。

## 实施阶段

### 阶段一：配置发现与只读状态

1. 在现有 `config/read` 和 `origins` 基础上建立“字段—读取接口—写入接口—作用域—协议版本—协议证据”矩阵，并记录响应中缺失字段的降级行为。
2. 对 App Server 未提供的字段，从 Codex CLI / `config.toml` 读取时明确标注为配置文件来源，不假设 CLI 输出就是线程最终配置。
3. 以 `config/read` 返回的 `origins` 和 `layers` 为准记录实际配置优先级；“组织策略 > 运行时参数 > 项目配置 > 用户配置 > 模型默认”只能作为待验证假设，不能直接写死。
4. 扩展配置值模型，避免把密钥、Base URL 等敏感值写入 UI 或历史。
5. 在设置页展示“当前值 + 来源 + 是否可编辑”；未取得协议证据的字段保持只读，不用提示词模拟行为。

### 阶段二：安全设置

1. 保留现有批准策略持久化，同时补充官方策略选项和说明。
2. 明确自动批准对命令、文件变更、浏览器和权限请求的影响。
3. 读取并展示 sandbox 模式；只有协议支持写入时才开放选择器。
4. 按设置类型决定生效方式：优先使用 `config/batchWrite` 的 `reloadUserConfig` 热加载可热加载字段；新任务默认值仅更新本地状态；只有确实改变 App Server 启动参数且运行时不支持热加载时才提示安全重连。
5. 配置写入或重连失败时恢复旧值，且较早的异步写入不得覆盖较新的选择。
6. 对设置变更增加协议、持久化、项目切换、失败回滚和权限回归测试。

### 阶段三：网页搜索与回复行为

1. 将网页搜索与内置浏览器拆成两个独立设置和权限边界。
2. 先记录官方选项的独立语义：已禁用、已缓存、已索引、实时；只有协议或官方证据证明等价时才允许合并展示。
3. 若协议支持，加入输出详细程度和推理摘要选项，并按模型能力动态禁用不支持项。
4. 搜索模式切换不得绕过网络安全检查、用户批准或私网地址拦截。
5. 不支持的字段继续显示“由配置管理”或“自动”，并提供查看配置入口；`reloadUserConfig` 明确不会热加载模型、推理强度、Plan 模式推理强度、服务等级和 personality 默认值。

官方 Schema 已确认字段并不等于当前稳定运行时已支持。只有 0.153.4 或升级后的目标运行时通过兼容性测试后，才可在设置页开放对应写入控件。

### 阶段四：官方体验验收

1. 记录官方客户端的选项顺序、文案、默认值和菜单禁用条件。
2. 对齐深色/浅色主题、卡片布局、行高、下拉菜单和勾选状态。
3. 覆盖窄窗口、键盘导航、读屏语义和配置保存失败。
4. 将实测证据补入 [CODEX_COMPOSER_PARITY_BASELINE.md](../CODEX_COMPOSER_PARITY_BASELINE.md)，把未完成项记录到 [CODEX_COMPOSER_PARITY_FOLLOWUP.md](CODEX_COMPOSER_PARITY_FOLLOWUP.md)。

## 验收标准

本计划还必须满足 [`docs/README.md`](../README.md) 中的“与官网一致”统一完成定义；下面的设置专属标准不能替代官方行为、协议和视觉证据。

- 设置页不显示与实际能力不符的可编辑控件。
- 每项设置都能说明当前值和配置来源，或明确说明为什么不可编辑。
- 配置快照能区分字段缺失、字段为 `null`（继承默认值）和字段有明确值，三种状态在设置页文案和可编辑性上不能混淆。
- 每项设置都明确用户级、项目级、线程级或模型级作用域，并验证项目切换不会污染全局默认值。
- 批准策略和沙盒的安全边界有协议测试和 UI 测试。
- 配置写入失败、重连失败、快速连续修改和应用重启均会保留或恢复正确的旧值/新值。
- 网页搜索不会错误复用内置浏览器设置。
- 网页搜索的“已缓存”和“已索引”不会在缺少证据时被错误合并。
- 设置变更在应用重启、运行时重连和切换项目后保持正确隔离。
- 完成用户可见能力后同步更新 `README.md`、`ROADMAP.md` 和 `RELEASE_NOTES.md`。

## 推荐代码落点

- `lib/src/presentation/settings/codex_workspace_settings_page_state.dart`：设置行、菜单、来源和禁用状态。
- `lib/src/services/runtime_configuration_store.dart`：默认设置持久化。
- `lib/src/app_controller_codex_controller_runtime.dart`：配置加载、协议发送、重连和错误恢复。
- 新增独立 domain / provider 文件承载不可变配置快照；跨组件和异步状态优先使用 Riverpod。
